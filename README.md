# Ритм — дневник тренировок

React + TypeScript + Vite, устанавливаемое PWA, Supabase. Интерфейс на русском, адаптирован для телефона и компьютера.

## Запуск

```sh
npm install
npm run dev
```

## Подключение Supabase

1. Создайте проект Supabase.
2. Выполните `supabase/schema.sql` в SQL Editor.
3. В Authentication → Providers включите Anonymous sign-ins.
4. Скопируйте `.env.example` в `.env.local` и заполните URL проекта и публичный anon/publishable key. Не используйте service_role key.
5. Перезапустите приложение.

Без переменных окружения используется локальное хранилище браузера. При подключении Supabase создаётся анонимная сессия; дневник изолирован через RLS. При первом подключении локальный дневник переносится в облако, если облачный дневник ещё пуст. Существующий облачный дневник имеет приоритет. Анонимная сессия привязана к браузеру: для постоянного входа с разных устройств потребуется добавить авторизацию через email. Очистка данных браузера теряет доступ к анонимной учётной записи.

Изменения сохраняются локально сразу и отправляются в Supabase с задержкой. При возвращении сети отправка повторяется. Приложение рассчитано на одну активную сессию редактирования: одновременное редактирование в нескольких вкладках не объединяется.

## Возможности

- Начало и завершение тренировки, автоматический расчёт времени между первым и последним добавленным подходом, восстановление после перезагрузки.
- Библиотека с поиском, фильтрацией, созданием и редактированием упражнений; несколько групп мышц.
- Вес, повторения и отметка выполнения каждого подхода; добавление и удаление подходов и упражнений.
- История с подробностями, объём, количество подходов, время, активность недели.
- PWA: манифест, иконки, service worker, офлайн-кэш оболочки. Установка через кнопку или меню браузера.

## Сборка

```sh
npm run build
npm run preview
```

Для установки PWA нужен HTTPS (localhost подходит для разработки). Service worker генерируется в production-сборке. Деплойте содержимое `dist` на статический хостинг.

## Загрузка старых тренировок

На страницах «Обзор» и «История» есть кнопка «Загрузить тренировку». Вставьте запись, проверьте предпросмотр и подтвердите загрузку. Формат: `9 нояб. 2026 | 50 мин`, затем названия упражнений с `🔹` и подходы `40кг*12, норм`. Поддерживаются `размин`, `легко`, `норм`, `тяжел` / `сложно`, дробный вес, обычные табуляции и `&#x9;`.

Знакомые упражнения сопоставляются по названию с учётом `е/ё`, пунктуации и порядка слов. Остальные добавляются в библиотеку без выдуманных групп мышц. Разминки и сложность сохраняются; все импортированные подходы отмечаются выполненными. Повторная загрузка той же записи блокируется. Длительность берётся из исходной записи, поскольку времён отдельных подходов там нет; дата интерпретируется по Москве, точное время начала в исходной записи не задано. Пример для проверки: `tests/fixtures/workout.txt`.

## GitHub Pages

В `.github/workflows/deploy.yml` настроена автоматическая публикация при обновлении `main`. В Settings → Pages выберите GitHub Actions. В Settings → Secrets and variables → Actions → Variables задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (только публичный publishable key). Административные ключи здесь не нужны.

Путь приложения, манифеста и service worker определяется автоматически из адреса Pages. Для проверки локальной сборки в подпапке установите `VITE_BASE_PATH=/ritm/` перед `npm run build`. Локальный запуск по умолчанию использует корень `/`.

Анонимная сессия хранится отдельно для каждого домена. Смена localhost на GitHub Pages не переносит браузерную сессию автоматически; записи остаются в Supabase, но для доступа к прежнему дневнику с другого домена потребуется привязанный способ входа или отдельный перенос.

## Общий дневник без email

Кнопка «Личный код» позволяет создать код в браузере с нужной историей и ввести его в другом браузере. Код состоит из 32 случайных шестнадцатеричных символов (с разделителями). Это ключ полного доступа; его следует хранить как пароль. Сервер хранит только SHA-256 хеш. Новый код отменяет прежний для новых подключений; уже подключённые браузеры сохраняют доступ.

Подключение не удаляет прежний дневник браузера. Общие данные читаются и сохраняются через защищённые RPC; таблицы связей и хешей находятся в закрытой схеме `private`. Сохраняется один общий дневник, а не копии. Обновления подгружаются при фокусе окна и каждые 15 секунд, пока страница видима и нет несохранённых изменений. При конфликте версий запись отклоняется, изменения сохраняются локально в `ritm-conflict-backup` — приложение просит обновить страницу.

## Питание и справочник

В разделе «Справочник» создаются продукты и собственные типы. Для продукта указываются название, тип, белок и калории на одну порцию. Вес порции не требуется. Продукты и типы можно редактировать.

В «Питании» кнопка «Добавить» открывает выбор продуктов с поиском, фильтром по типу и количеством порций. Несколько выбранных продуктов сохраняются одним приёмом пищи. Сверху дня отображаются суммарные белок и калории, ниже — приёмы пищи со временем и составом. Итоги считаются по Москве. Сводка последних семи дней сохранена.

Приём пищи хранит значения продукта на момент добавления: изменения справочника не переписывают старые итоги. Данные сохраняются в полях `foodProducts`, `foodTypes`, `meals` общего дневника Supabase. Старые счётчики порций (`nutrition`) сохраняются и отображаются отдельно без выдуманной калорийности; в новые итоги они не включаются.

## Ежедневные отметки на обзоре

Под статистикой показаны фрукт, овощи и витамины: отмечено / ещё нет. Записи питания с соответствующими типами или названиями учитываются автоматически; отметку можно исправить вручную. Новая дата по Москве начинает новые отметки. В четвёртой карточке расположен счётчик стаканов воды с кнопкой «+». Он учитывает отдельные добавления на обзоре и воду из дневника питания. Данные хранятся в `dailyHabits` и `waterGlasses` в том же защищённом дневнике.
